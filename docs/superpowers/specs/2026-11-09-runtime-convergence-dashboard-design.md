# XX-Net 真实工作流收敛与运行 Dashboard 设计

日期：2026-11-09

## 1. 背景与本轮要修正的方法缺陷

上一轮审计建立了变化分母、核心流程、R/S/C/D 分级和完整离线套件，但生产仍出现下载截断。已确认的反例是：测试只证明“X-Tunnel 乱序队列超过 1 MiB 必须关闭”，没有同时证明“协议允许的 10 MiB 窗口内，缺失命令可在重取后恢复”。局部保护测试全绿，却以正常下载能力为代价。

部署验收又使用了 `-no_popup -no_systray`。它证明了特殊无界面配置下的代理链路，不证明用户运行 `/Applications/XX-Net/start` 时的托盘、管理页面和退出行为。旧报告虽然列出完整桌面路径和生产性能趋势未覆盖，但这些缺口没有成为发布结论的机检阻断项。

因此，本轮不是简单增加测试数量，而是修正“需求如何变成 oracle、证据允许外推到哪一层、何时允许宣布收敛”。

## 2. 目标、非目标与反目标

### 目标

1. 将上一轮六项收敛条件扩展为真实用户工作流、跨层契约、测试有效性、生产等价性、持续观测和独立证据复核的闭环。
2. 用正常路径、目标异常、相邻异常和恢复路径共同约束每项保护，禁止只验证保护会触发。
3. 让真实 `./start` 的启动、托盘、管理页面、代理入口和正常退出成为独立验收入口。
4. 建立脱敏、低开销、可机检的运行指标和 Dashboard，展示用户结果、跨层压力、恢复、异常和资源平衡点。
5. 每轮由新证据调整计划；任何 Critical/Important 反例都回到契约、RED、最小修复和复验，不为完成旧计划而隐藏缺口。

### 非目标

- 不证明所有外部网络、所有平台或长期未知故障永久消失。
- 不为了 Dashboard 重写现有网络栈，不引入重型外部监控服务作为运行前提。
- 不重新放宽已经确认的 DNS 全调用期限、Task 完成语义、NS 全局 single-flight、transfer 协议身份、quota 回滚或 body queue 背压契约。
- 不在本轮执行 pip/xattr、真实 iptables、输入管理员密码、修改系统代理或其他系统设置。

### 反目标

- 用端口在线、HTTP 204、日志无 Traceback 或测试 GREEN 数量代替完整用户结果。
- 用 `-no_popup -no_systray` 的结果声称真实桌面验收通过。
- 把现有含账号、Host、IP、session_id 或完整调试文本的状态接口直接接入 Dashboard。
- 为了得到稳定曲线而过滤慢请求、失败样本或未知事件。
- 以“本轮暂不验证”为理由让依赖该证据的高风险结论继续显示通过。

## 3. 需求—不变量—证据闭环

每项验收卡必须包含：

- 用户或协议意图；
- 涉及的入口、模块、资源和跨层参数；
- 正常、目标异常、相邻异常、恢复和停止/换代五类独立 oracle；确不适用时必须记录固定理由，不能用“恢复或停止”二选一；
- 每个 oracle 对应的精确测试方法、实际运行结果，以及指标或人工证据；仅测试文件或名称存在不构成闭合；
- 测试能够检出的最小代码变化；
- 离线证据等级、生产证据等级和明确未覆盖项；
- 对应运行指标、告警或人工确认；
- 结论允许外推的边界。

测试存在但无法指出“哪个产品变化会使它失败”，视为测试意图未闭合。夹具错误、导入错误和超时不能冒充目标 RED。修复后必须保留原始失败记录。

## 4. 生产验收等价性分级

| 等级 | 实际入口与范围 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| E0 | 单元、真实类、socketpair、受控时钟、故障替身 | 局部契约和确定性交错 | 真实安装、桌面或外部网络 |
| E1 | 真实生产文件，显式 `-no_popup -no_systray` | 无界面服务、端口与代理数据面 | 托盘、自动页面、真实桌面退出 |
| E2 | 用户实际 `/Applications/XX-Net/start`，不添加降能参数 | 默认启动参数、模块、页面打开请求和真实代理链路 | 尚未观察的菜单交互、系统授权和长期趋势 |
| E3 | E2 加真实托盘/菜单和正常退出观察 | 用户完整启动—使用—退出流程 | 未执行的平台安装、提权或系统设置 |

每次验收记录入口、argv、工作目录、Python 可执行文件、代码根、配置来源类别、进程代际、桌面/托盘/页面状态和代理链路。记录只能是事实，不得把“请求打开页面”写成“用户已看到页面”。

E1 结果必须醒目标为“无界面服务验收”。涉及启动或桌面行为的交付只有在对应 E2/E3 证据通过后才能关闭；若密码或系统设置边界阻止验证，状态为 BLOCKED/未覆盖，不是 PASS。

真实入口调用前必须做无副作用的等价预检：按启动脚本实际分支选择解释器，以相同的 user-site 可见性和中性工作目录检查桌面模块，判断是否会进入自动 pip、解包、提权或系统设置分支。预检不能使用会改变模块可见性的 `-I` 结果替代真实事实。若会触发禁止的副作用，记录 `BLOCKED / START_NOT_INVOKED / AUTO_INSTALL_REQUIRED`，且不得调用 `./start`，也不得用无界面参数绕过。

真实生产事实必须先由生产校验器验证并生成绑定原始证据哈希的 verdict，再由证据门禁消费。E2/E3 所需事实、代码哈希、代码根、进程代际、默认 argv、探针和 Dashboard 健康均由机检；等级字段本身不是证据。

本轮终态分为：`CONVERGED`（全部收敛门槛满足）、`BLOCKED`（安全边界禁止继续，停止操作但不声称收敛）和 `FAILED`（已取得真实反例或验收失败）。

## 5. 跨层契约与双向兼容矩阵

### 5.1 X-Tunnel 下载恢复

联合冻结并验证：

- 协议下载窗口、最大协议块和 `Conn.cmd_queue` 字节上限；
- 缺失首个/中间/末尾命令；首、中缺口必须实际构造 `1 MiB < cmd_queue_bytes <= windows_size`，不能只凭测试名称推断；
- 合法乱序、永久缺口、超过 `windows_size + max_payload` 的真实越界反例和补包恢复；
- SN 重取期限、Conn 停止原因、本地 socket EOF 和调用方实际读满字节；
- 单 Conn、多 Conn 并发、Session 换代和旧事件晚到。

正常 oracle 是在合法窗口与重取期限内不主动杀死可恢复下载，原缺失命令到达后恢复按序处理；数据命令必须实际增加本地发送进度，调用方按序读满预期字节、EOF 语义正确且队列最终释放。异常 oracle 是永久缺口和真实越界仍有界关闭。普通 1 MiB 生产下载不能替代上述强制乱序向量，任何一侧缺失都不得关闭该契约。

### 5.2 DNS 与路由

联合验证全调用期限与各 transport 期限、并行旧结果交付、代际/epoch 提交、NS 全局 single-flight、缓存失败与系统解析回退。指标区分“调用按时返回”“返回空结果”“缓存被旧代写入”和“路由选择”，不得把 DNS 有响应直接等同为路由可用。

### 5.3 Front、HTTP/1、HTTP/2 与独立 Client

联合验证请求共享剩余期限、响应头/正文完整读、H2 stream 与连接所有权、retry 的协议身份、keep-alive 二次复用、失败 socket 回收和跨代晚到事件。正常慢响应、合法 peer、部分写入、超时和停止必须有成对证据。

### 5.4 Smart Router、PipeSocks 与模块开关

联合验证连接交接前后所有权、读写集合增删、背压、对端关闭后的剩余数据、X-Tunnel 开关刷新和停止/重启。状态接口不得泄露 socket 对象、目标 Host 或对端地址。

### 5.5 Launcher 与真实桌面

验证默认参数解析、重复启动防护、页面打开请求、托盘初始化成功/降级、退出幂等和清理失败语义。不得通过 mock 的 AppKit 结果声称真实菜单已点击；真实密码弹窗、系统代理和提权路径单独标记。

## 6. 测试有效性与动态收敛

### 6.1 测试必须能抓住原缺陷

每项新保护至少采用一种有效性证明：

1. 在未修复真实实现上准确 RED；
2. 定向变异或临时反转使 GREEN 重新变 RED；
3. 故障注入证明探针和 Dashboard 能显示目标异常。

仅增加覆盖率、重复运行或断言 mock 被调用不算有效性证明。优先使用本地 Hypothesis 属性测试处理乱序、重复、晚到、停止与边界组合；不具备确定性复现价值的随机用例必须记录 seed，并可收缩为固定回归。

### 6.2 计划随证据调整

每一轮结束重新计算：

- 新增或失效的契约和测试；
- 新反例及其影响的其他层；
- 证据是否支持当前措辞；
- 监控是否能区分正常退化与保护误杀；
- 尚未覆盖项是否阻断任何通过结论。

发现 Critical/Important 时，暂停无关实现，返回对应契约和 RED/GREEN；发现工具或采集器错误时，先修复验收工具，不能修改产品去适应错误探针。所有计划变更进入台账。

## 7. 运行监控点目录

指标必须能改变诊断或验收行为。采集使用白名单数值和固定枚举，不采集 URL/query、Host、DNS 名称、IP、Cookie、Authorization、账号、密码、token、session_id 或响应正文。

schema v1 必须逐字段固定名称、类型、单位、累计/瞬时节语义和缺失规则；矩阵引用的指标键必须与实际 snapshot 自动对照。累计计数器只接受正整数增量并跨模块重启保持进程级单调；可能下降的在途量使用独立 gauge。目标 macOS 的最低资源字段包括线程数、RSS、CPU 累计时间、fd 数和 fd 软限制，持续缺失会阻断对应资源结论。

### 7.1 用户结果与入口

- 固定探针尝试数、完整成功数、失败分类、字节完整性、时延；
- 控制页、HTTP、HTTPS、SOCKS5 域名入口可用性；
- 启动模式、进程代际、模块运行状态、托盘/页面请求状态。

“完整成功”必须同时满足协议状态和预期正文边界，不能只统计获得响应头。

### 7.2 X-Tunnel

- Session 活跃 Conn 数、transfer 数、在途请求数、上下行累计字节和速率；
- `SendBuffer` 字节、单 Conn 发送缓冲、`cmd_queue` 字节及其相对协议窗口比例；
- 乱序缺口年龄、缺口恢复、SN 重取、慢/超时 roundtrip；恢复只在原缺失命令到达并恢复按序处理后计数，数据命令还须观察到本地发送进度前进。超时、关闭、清空、重置和换代不得计作恢复；
- 受控停止原因计数，至少区分队列溢出、永久缺口、正常 peer 关闭、网络错误和换代停止。

核心告警：合法窗口内发生本端队列溢出、永久缺口反复发生且没有恢复、完整成功率下降而队列压力上升。

### 7.3 Front/HTTP

- 每类 front 的 worker 数、H1/H2 数、待处理任务、成功/失败和 RTT；
- 新连接池数量、连接创建中数量、无可用 IP 事件；
- 请求重试、响应失败、正文期限到期、协议异常和换代丢弃计数。

front 名称使用固定协议类别；不导出实际目标主机、IP 或 trace。

### 7.4 Smart Router/DNS/PipeSocks

- DNS 调用数、完整结果/空结果/超时、总时延、并行代际淘汰和缓存提交拒绝；
- 路由结果分类计数、连接交接失败、Pipe 读写 socket 数、写缓冲和受控关闭；
- 缓存仅导出容量、条目数和 epoch，不导出键。

### 7.5 进程与日志健康

- 线程数、RSS、CPU 累计时间、fd 数和 fd 软限制；
- 日志持久队列长度、丢弃记录数、写入失败数、throttle 抑制计数；
- 后台未捕获异常和未知停止原因。

绝对资源阈值必须来自真实基线和 fd 限制，不能把任意机器经验值写成普遍标准。趋势用于比较同机同负载，不用一次快照声称性能优化。

## 8. 本地采集与 Dashboard 架构

### 8.1 架构选择

采用进程内只读 snapshot 提供器、launcher 白名单聚合接口和本地 Web Dashboard。默认不依赖 Prometheus、Grafana、OpenTelemetry Collector 或外部账号；调研结果若显示未来确有必要，可另行导出适配层，但不让外部服务成为本轮验收前提。

采集器只调用明确的安全 snapshot 方法，不读取完整配置、不解析 `/debug` 明文、不把现有 `/status` 原样转发。单个模块未启动或采集失败返回固定状态，不影响其他模块，也不改变网络路径。`/runtime_metrics` 必须位于现有控制面认证、Referer 和监听边界之后，不新增 CORS 或许可；页面 snapshot 不包含完整 argv、cwd、可执行路径等本地验收事实。

snapshot 禁止嵌套持有网络锁与指标锁；网络锁采用非阻塞获取，失败字段为 `None`，锁内只复制少量数值并在锁外聚合。聚合器对每个 provider 至少保留一个有界期限和单在途执行，超时返回固定 `unknown`，不得因重复轮询无限堆积阻塞线程。

探针导入使用版本化白名单 schema，允许固定类别、预期/实际字节、状态、时延和可选内容 SHA256；额外或缺失字段一律拒绝。代际比较基准必须来自当前 `/runtime_metrics`，不能由被导入文件自行声明。

### 8.2 采样、保留与开销

- 页面采用“上次完成后再计时”的单在途采样，目标间隔 5 秒，支持 abort 并拒绝迟到/乱序响应；请求失败时当前样本标为 stale/unknown，不能沿用最后成功样本冒充当前健康；
- 浏览器最多保留最近 360 个有效样本，实际窗口按首尾有效采样时间显示，页面刷新后明确开始新观察窗口；
- 快照包含采样时间、进程代际、采集耗时和缺失模块；累计计数跨模块重启保持单调，模块运行状态变化时重置页面差分基线，旧进程代际样本不得与新一代拼接成同一资源趋势；
- 默认不写历史数据库；需要长期窗口时另立存储与保留设计，不能把当前 30 分钟页面冒充长期监控；
- 采集失败必须显示为未知，不用 0 填充；
- 本轮最短观察窗口为实际起止时间至少 60 秒、至少 6 个有效样本，允许缺口须预先登记；样本容量不等于实际观察时长；
- 每条故障注入证据记录 E0/E1/E2 来源、独立实例标识、代码哈希和进程代际，低等级注入不能补足生产故障证据；
- 快照不得持有网络全局锁执行 I/O，不主动触发建连、DNS 查询、网络检查或清理。

### 8.3 页面视图

1. **总览**：观察窗口内完整成功率、失败数、RTT、活跃连接、资源快照和采集健康；无请求时显示“无样本”，不显示 100%。
2. **用户链路**：固定探针结果及失败分类，与启动代际和模块状态对齐。
3. **跨层压力**：X-Tunnel 队列/窗口比例、SN 重取与恢复、Front worker/重试、DNS 空结果/超时按时间对齐。
4. **资源与生命周期**：线程、RSS、fd、队列和连接趋势；换代使用分隔线，禁止跨代直接比较累计计数。
5. **异常与平衡点**：受控停止原因、保护触发、恢复是否成功、日志丢弃和采集缺失。
6. **证据边界**：当前 E0—E3 等级、启动参数摘要、观察窗口和未覆盖项。

阈值分两类：协议不变量违反可直接告警；性能和资源阈值先显示基线/容量比例，只有经过同机基线测量才设为结论性门禁。

## 9. 工具采用边界

工具调研和一手来源记录于 `docs/research/2026-11-09-qa-review-tools.md`。采用原则是补足证据，而不是按热度堆叠：

- **本轮立即采用**：本地意图/契约审计、未参与设计者的独立审查、验收证据门禁、确定性 Event/Barrier 交错、定向变异/反转和本地故障注入；这些不依赖新账号或代码外发。
- **本地可选试点**：Hypothesis 用于扩大合法交错输入，mutmut 用于抽查测试有效性，Semgrep/CodeQL 用于固化已知反模式；只有确认现有环境可用后才执行，不为了本轮临时安装依赖，也不把扫描或变异分数当作并发正确性证明。
- **本轮不启用**：Qoder/Qodo/CodeRabbit 等需要云端评审、私有仓库权限、付费账号或 PR 写入权限的工具。其本地 CLI/IDE 形态不等于代码不出网；未来若在合成样例或获准代码上试点，须另行明确批准。
- **后续再评估**：OpenTelemetry、Prometheus、Grafana 适合长期存储和跨进程观测，但不是本轮本地 Dashboard 的运行前提；需要历史趋势时再另立适配层和保留设计。

## 10. 安全与操作约束

- 沿用当前普通 checkout 和 `fix/h-log-dns-backoff`；不新建 worktree，不自行 commit、push、合并或创建 PR。
- 优先使用 CodeGraph，再核实真实源码；独立审查结果只是候选，重要发现由主线程核实。
- 项目及不可信下载相关 Python 使用 `python3 -I`；不执行真实 iptables，不输入密码，不提权，不修改系统代理。

## 11. 收敛门槛

只有以下条件同时满足，才可以 `CONVERGED` 停止本轮规划—执行循环。若安全预检要求自动安装、提权或系统设置，则以 `BLOCKED` 停止相关操作并保留证据，不宣布收敛；若取得真实反例或验收失败，则以 `FAILED` 返回对应契约修复：

1. 新验收卡、跨层契约、测试和生产入口分母闭合，需求与证据可双向追踪。
2. 已知下载反例及其相邻正常/异常/恢复场景通过；新发现 Critical/Important 全部完成 RED/GREEN 和关联回归。
3. 测试有效性经原始 RED、定向反转或故障注入证明；完整 manifest 无失败、漏跑、未声明 skip、超时或后台异常。
4. 默认真实 `./start` 达到 E2；托盘和正常退出若无法在安全边界内自动验证，明确保持 E3 未覆盖，并阻止“完整桌面验收通过”的措辞。
5. Dashboard 使用真实运行数据，能展示总览、跨层压力、资源、异常和证据边界；异常注入可被探针和页面同时观察。
6. 独立复核确认结论没有超出证据，未覆盖项已机检阻断相关通过结论；所有计划调整、失败和裁定均进入台账。
7. 若本轮修改并部署产品，仓库/生产哈希、真实进程代际、默认启动入口、代理数据面和观察窗口日志均通过；失败则恢复并验证。
