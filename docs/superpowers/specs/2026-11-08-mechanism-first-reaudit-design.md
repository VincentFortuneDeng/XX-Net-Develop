# 故障机理驱动的网络可靠性复审设计

日期：2026-11-08

## 意图

重新执行一轮完整审计，但不是重复按文件扫描或复述既有问题。先总结历史故障机理，映射实际执行流、共享状态、跨层调用与生命周期，再针对多个执行流和功能组合后的顺序进行检查。确认问题后按测试驱动修复，并在完整回归通过后部署、重启和验证，直到没有未处理的 Critical/Important 问题。

## 历史缺陷的机理归纳

1. **迟到执行流仍持有控制权**：旧 attempt、旧 session、旧 Conn、旧 checker、旧 DNS worker 在新对象接管后继续写状态或清理资源。
2. **检查与动作被拆开**：状态检查、登记、取数、消费、删除和恢复不在同一身份边界，异常时序可穿过窗口。
3. **资源所有权交接不完整**：缓冲字节、socket、连接映射或待发送数据在回退、停止和首次注册失败时没有明确接收者或关闭者。
4. **平行实现语义漂移**：H1/H2/独立 Client，以及 UDP/TCP/DoH/xx-net/system 对同一协议语义采用不同规则。
5. **期限被逐阶段续期**：多个地址、连接、TLS、响应头、正文或重试分别取得完整 timeout，破坏调用级预算。
6. **锁与生命周期顺序冲突**：管道锁与会话锁反向获取；发布、运行、异常、退出、接替和清理之间存在失控空窗。
7. **证据链失真**：测试替身缺少真实状态、全局模块替身串扰、短时正常或重复成功被误当成间歇问题永久治愈。

## 本轮审计坐标

### 执行流与共享状态

- front：dispatcher、H1/H2 worker、Task/Stream、连接 checker、响应消费者；共享 Task 状态、attempt、retry 队列、stream 注册表和连接。
- Smart Router：请求解析、路由决策、GAE/X-Tunnel/direct 回退、SocketWrap/PipeSocks；共享请求缓冲区、socket 所有权、pipe 成员和运行状态。
- DNS：调用线程、UDP 接收线程、TCP/DoH/xx-net/system 来源、超时清理、缓存和 NS backoff；共享 waiter、ID、代际、缓存 epoch 和退避状态。
- X-Tunnel：处理器、Session、roundtrip worker、ConnectionPipe/Conn、checker、login；共享 transfer、send/receive buffer、on_road、连接映射和全局 session。
- 跨模块生命周期：launcher、module start/stop、全局对象替换、配置重载、前端与后台线程；检查旧模块线程是否仍能影响新实例。

### 时序切面

对每条链检查“创建→登记→发布→运行→回调→异常→退出→接替→清理”，并重点交换以下事件顺序：

- stop/reset/clean 与正在等待的网络返回、登录、建连、注册和缓存写回。
- close/retry/finish/timeout 与新 attempt、新 worker、新 stream 的接管。
- ACK/背压恢复与 checker/reset，socket 注销与同号新 Conn 注册。
- 首包缓冲、部分写入、协议回退和 PipeSocks 发布。
- 单 stream 错误与共享 H2 连接，单来源 DNS 响应与其他 waiter/来源。
- 模块初始化失败、重复 start/stop、旧线程退出与全局对象替换。

### 异步交接状态表

计时器、队列和回调不能只作为函数名出现，必须分别建模“事件发生”和“实际执行”：

- 计时器：`schedule → cancel/fire → execute → rearm`；取消后迟到的 fire 仍须在 execute 时核对身份与状态，区分单调时钟和墙钟。
- 队列：`enqueue → dequeue → complete`；检查消费者退出、队列满、重复完成、完成回调丢失及旧队列项跨重启执行。
- 停止：`stop 开始 → 发布停止边界 → stop 返回 → 线程实际退出 → restart`；不得把 stop 返回等同于所有旧执行流已经消失。
- 回调：明确是否持锁、是否可重入、是否可能触发反向清理；回调实际执行时重新核对对象身份。

### 故障扩散边界

分别记录 stream/request、connection、session、module 和全局记账允许被哪些事件取消、重试、清理或修改。单 stream 错误不能默认扩大为连接级失败，单连接错误不能默认重置 session；旧请求的真实全局消耗与旧对象的状态控制分开判断。

### 平行实现与期限

对同一输入分别走 H1/H2/独立 Client 或不同 DNS 来源，比较正文完整性、响应归属、地址族、重试、连接复用和资源关闭。所有阶段检查是否共享调用方预算，且不将单任务期限误施加到共享连接。

## 证据与分级

- **R**：真实代码配合可控替身、事件门或本地 socket 的确定性复现。
- **S**：源码可以推出完整触发与影响路径，但尚未动态复现。
- **C**：行为存在，是否违反接口或统计契约仍需设计裁定。
- 独立审查只提供候选；重要发现必须由主线程核实。生产日志只能支持关联，不能替代根因证明。
- 分别记录代码行为置信度、契约状态、影响严重度、生产可达性和事故归因置信度，不把 R/S/C 与严重度混为一个轴。
- 建立“事故/症状→已观察证据与未知项→候选机理→跨层 happens-before→不变量→反例/复现→覆盖结果”矩阵。无法由现有生产证据解释的症状保留为未知，不用代码候选反填历史根因。
- R 条目注明真实版本、配置前提及哪些条件由替身人为制造；重复通过只证明特定模型，不证明生产发生率。

## 修复与验收规则

- 确认的缺陷先取得准确 RED，再做最小 GREEN；保留正常路径正反例，不通过放大超时或放宽断言制造通过。
- 修复围绕所有权、代际、状态机和共享期限组织，避免单点修补破坏相邻路径。
- 完整测试按文件独立进程运行，以规避既有全局替身污染；关键竞态重复并扫描后台异常。
- 部署前先确认实际运行目录与开发目录差异，保留既有备份和日志；仅在回归通过后同步、重启。
- 部署验收包括代码一致性、进程代际、旧进程退出、本地控制接口、经代理的实际请求及脱敏日志检查。保存部署前基线，针对原症状做前后对照；日志顺序不能单独充当并发反证。
- 明确回滚条件：新进程无法就绪、控制接口失败、代理基本请求持续失败或出现指向本轮修改的新异常时，停止继续验收并恢复原运行文件。间歇问题需要覆盖历史复发周期的后续观察窗，短时正常不作为永久治愈证据。
- 不读取或输出账号、密码、token；日志及派生分析中的 session_id 使用伪造值或脱敏值。不执行真实 iptables，不自行 git commit/push/merge/PR。

## 收敛标准

所有本轮确认的 Critical/Important 均有回归测试并完成部署验证；完整套件与关键竞态通过；独立最终复核无未处理高优先级问题。最终只声明“已覆盖模型内没有未处理高优先级项”，不推出整个系统不存在未知问题。C 级契约与低价值 Minor 单独记录，不通过扩大范围伪装“全部解决”。
