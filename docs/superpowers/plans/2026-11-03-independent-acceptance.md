# 2026-10-26 以来全部变更的独立验收计划

**目标：** 不以既有 TDD 测试通过作为合格依据，重新从使用者和故障现场角度验收 23 张变更卡，主动寻找开发阶段未覆盖的反例。

**执行约束：** 直接执行；不重启、不部署新代码、不 push；生产只做只读检查、正常 Web 请求和代理连通性检查。破坏性、异常时序和资源故障仅在临时目录、替身边界或独立 socket 中注入。旧日志和备份不删除。

## 为什么这次能发现 TDD 漏项

1. **生产黑盒：** 从真实进程、端口、HTTP 和文件观察结果，不调用测试中的断言辅助函数。
2. **独立模型/差分：** 用简单参考模型计算应有结果，与真实实现比较；业务行为在“原日志路径/新日志路径”之间做状态差分。
3. **随机与 metamorphic 验收：** 随机 Unicode、记录尺寸、键集合、事件顺序、异常组合和文件预算；验证不依赖具体样例的不变量。
4. **故障注入：** 首次打开失败、滚动失败、畸形 UTF-8、半条记录、模块缺失、资源 stop 失败、DNS/socket 失败和并发关闭。
5. **压力与生命周期：** 多线程、反复 stop/reset、迟到事件和全组合清理异常，寻找原子性、封口、原异常遮蔽与资源泄漏。
6. **独立红队：** 未参与实现和本验收脚本编写的 reviewer 从 23 卡反查代码与证据，专门寻找“测试和实现共享同一误解”的缺陷。

## 判定规则

- **PASS：** 有本次新产生的独立证据，且反例为零。
- **FAIL：** 得到可复现反例；记录输入、实际/期望、影响范围，先修复再复验。
- **UNVERIFIED：** 需要 GUI、真实远端特殊故障或主动重启/上传等本轮未授权条件；不得写成 PASS。
- **ACCEPTED RISK：** 有证据表明是明确设计取舍而非实现错误，必须说明实际代价。
- 原有测试只作回归背景，不代替本矩阵。最终报告按 23 项逐项列证据，不用一个“全套绿”掩盖未覆盖项。
